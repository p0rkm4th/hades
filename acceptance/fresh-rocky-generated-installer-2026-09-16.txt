HADES fresh Rocky generated-installer acceptance

Environment
- Disposable Proxmox HADES guest on hypervisor host; Rocky Linux 10.2; no production state.
- Inputs were generated by scripts/create-generated-private-inputs.sh and
  deployed by scripts/install-hades.sh from the tracked contracts.
- Hermes 0.14.0 was installed from the verified upstream artifact.
- A disposable OpenAI-compatible model fixture supplied the synthetic model.

Acceptance
- Host preflight passed.
- HADES component deployment passed for LLDAP, Open WebUI, Hindsight, Grocy,
  Agent Zero, SearXNG, and Hermes.
- Doctor and install validation passed after normal LLDAP warm-up.
- Hermes health and authenticated /v1/models passed through the private Docker
  bridge address; the stale/incorrect key returned 401.
- Hermes was not bound to the LAN; its API listener was limited to the Docker
  bridge address.
- Open WebUI reached Hermes through host.docker.internal and discovered the
  hermes-agent model.
- Synthetic Alpha/Beta application acceptance passed: Alpha's response was
  persisted, Beta could not retrieve Alpha's private chat, Alpha's chat
  survived an Open WebUI restart, and Beta remained isolated afterward.
- Temporary signup enablement was used only to create disposable test users;
  the database and test state were removed afterward and signup was restored
  to false.

Reboot acceptance
- HADES guest was rebooted after cleanup. Docker returned the six application
  containers, the enabled Hermes service returned active, and Open WebUI and
  LLDAP returned healthy after normal warm-up.
- After the disposable model fixture was restarted, the private Hermes model
  route returned a synthetic response and the stale API key remained rejected.
- The model fixture is an external host dependency and was intentionally
  started separately after reboot; it is not a production service claim.

Repairs exposed by this run
- Generated Hermes and Open WebUI API keys now share one generated value.
- Generated Hermes binds to an explicit private Docker-host mapping instead of
  assuming container-local loopback.
- The generated service explicitly sources the protected Hermes profile env at
  launch without copying secrets into the systemd unit.
- The generated synthetic profile selects the model advertised by its fixture.
- The synthetic OpenAI backend now supports streaming responses, as required
  by the Hermes client.

Boundary
- This proves the v2 generated installer/application path on a fresh Rocky
  guest with synthetic inputs. It does not promote Hermes production, change
  the live HADES laptop, or qualify the unreachable physical deep inference provider/specialized inference provider
  hosts.
