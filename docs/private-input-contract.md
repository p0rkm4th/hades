# Private input and secret contract

This is the public description of the values required to reconstruct a
production-capable deployment. Values are supplied through the operator input
file or a referenced `0600` file; no live value belongs in Git, CI, doctor
output, or reports. The operator owns rotation and backup custody.

| Input | Consumer | Required | Format / supply | Read permission | Regenerate / rotation | Backup |
|---|---|---:|---|---|---|---|
| `HADES_OWNER_BOOTSTRAP_ID` | reserved compatibility name | no; unused | no current installer or runtime component reads this legacy value; do not rely on it to create or grant an owner identity | none | remove from private inputs; use the explicit `HADES_OWNER_SUBJECT_IDS` policy input instead | none |
| `HADES_OWNER_SUBJECT_IDS` | Hermes HADES policy | optional; owner-gated | comma-separated exact Open WebUI subject IDs without spaces, verified against the intended LLDAP owner account; no name/email inference | Hermes service only, through a root-owned mode-0640 generated environment file readable by its service group | update only after authenticated identity/group verification; empty removes the generated owner mapping | protected configuration backup |
| `HADES_EPSILON_PHASE3_DIRECTORY_AUTHORITY_FILE` | Epsilon Phase 3 runner | optional; gated | explicit stable Open WebUI subject → LLDAP user mapping plus fixed group-to-resource grants; mode 0600 | Epsilon service user only | preserve subject mappings; update group grants only under owner policy | encrypted private configuration backup |
| `HADES_EPSILON_PHASE3_LLDAP_URL` | Epsilon Phase 3 runner | optional; gated | verified HTTPS URL or node-local loopback HTTP URL | Epsilon service user | operator-controlled endpoint migration | configuration reference |
| `HADES_EPSILON_PHASE3_LLDAP_READER_PASSWORD_FILE` | Epsilon Phase 3 runner | optional; gated | file for a dedicated `lldap_strict_readonly` account; exact mode 0600 | Epsilon service user only | rotate reader credential with the directory procedure | encrypted secret backup |
| LLDAP JWT secret, key seed, admin password | LLDAP | yes | three file-backed random values under `HADES_IDENTITY_SECRETS_DIR`, mode 0600, UID 1000 | LLDAP only | generated once; rotation requires identity restore/revocation procedure | encrypted canonical identity backup plus key policy |
| `HADES_HERMES_API_KEY` | Hermes/Open WebUI private record | yes | random file-backed or private environment reference | Hermes/WebUI service account | rotate with client configuration update | encrypted private secret backup |
| `HADES_OPEN_WEBUI_LDAP_APP_PASSWORD` | Open WebUI | yes for LDAP sign-in | must match the LLDAP bind account password in the protected identity secret directory | Open WebUI container only | rotate in LLDAP, then update the protected operator input and rerun install | encrypted private secret backup |
| `HADES_HERMES_API_BIND_HOST` | Hermes systemd service | yes for v2 | verified Docker bridge gateway address so containers can connect; do not bind `0.0.0.0` | Hermes service | update with Docker bridge/network changes | no |
| `HADES_HERMES_API_BASE_URL`, `HADES_HERMES_CONTAINER_API_BASE_URL` | host preflight / Open WebUI | yes for v2 | host-local URL and container-reachable URL for the same Hermes API | installer/Open WebUI | update with Hermes API routing | no |
| `HADES_OPEN_WEBUI_BIND` | Open WebUI | optional; defaults to loopback port 3000 | host bind address and port; keep loopback unless a reviewed private access proxy is configured | Docker host | update with private access configuration | no |
| `HADES_HERMES_WORKING_DIRECTORY` | Hermes profile MCP commands and service unit | yes for v2 | absolute path to the checked-out HADES repository | Hermes service account | update with repository relocation and rebuild the profile | no |
| `HADES_WORKSPACE_ENABLED`, `HADES_HERMES_SANDBOX_IMAGE` | Hermes workspace actions | disabled by default | set enabled to `true` only after Hermes' workspace route is qualified; image must be an installed immutable `@sha256:` reference. Subject workspaces are created mode 0700 under the Hermes profile at `workspaces/<authenticated-subject>`; only that directory is mounted into the per-chat rootless container, with network and environment forwarding disabled. A rootful Docker socket is not an acceptable runner. | Hermes service account; rootless Podman or rootless Docker only | disable by setting `false`; never grant `hades-runtime` rootful Docker socket access | source workspaces from their canonical host/repository; generated empty workspace contents are not a source backup |
| `HADES_OPEN_WEBUI_SECRET_SOURCE` | Open WebUI | generated if absent | stable 32-byte signing key at a mode-0600 path; generated inputs provide it explicitly, otherwise installer creates it once under the state root | container runtime only | preserve across reruns and backup/restore | include with canonical private secrets |
| `HADES_HERMES_MODEL_ENDPOINT` | Hermes | yes | `http(s)` URL; local inference is optional and may be remote | Hermes | endpoint change is an operator migration | no, unless configuration backup requires the reference |
| `HADES_GROCY_URL` | Hermes recipe-ingestion adapter | yes for recipe ingestion | private host-local Grocy URL; default generated Compose mapping is `http://127.0.0.1:7003` | Hermes runtime only | change with the Grocy host port | no |
| `HADES_OLLAMA_BASE_URLS`, `HADES_FAST_OLLAMA_API_BASE_URL` | Open WebUI native model catalog / optional fast route | optional | explicit private model endpoints; empty disables these optional routes | Open WebUI | change with the selected model hosts | no |
| `HADES_HERMES_CONTAINER_MODEL_ENDPOINT` | Hindsight Compose | v2 optional when model runs on host | URL reachable from containers; generated records use `host.docker.internal` rather than container-local loopback | Hindsight | change with the model endpoint | no |
| `HADES_HINDSIGHT_LLM_BASE_URL` | Hindsight Compose | v2 optional dedicated extraction route | OpenAI-compatible local endpoint reachable from the Hindsight container; falls back to the Hermes model endpoint when absent | Hindsight | change with the selected local extraction lane | no |
| `HADES_HINDSIGHT_LLM_MODEL` | Hindsight Compose | v2 optional dedicated extraction model | Local model name served by the selected Hindsight endpoint; defaults to the deployment's qualified extraction model | Hindsight | change only with a bounded model probe | no |
| `HADES_HERMES_CONTAINER_API_BASE_URL` | Open WebUI Compose | v2 optional when Hermes runs on host | Hermes API URL reachable from the WebUI container; generated records use `host.docker.internal` rather than container-local loopback | Open WebUI | change with Hermes API routing | no |
| Hindsight database/auth values | Hindsight | yes | private record/file-backed values | Hindsight and Hermes only | rotate with native database procedure | native PostgreSQL export plus secret policy |
| Grocy API key | Grocy adapter | yes | plaintext key issued by this Grocy instance through its authenticated Manage API keys page; mode 0600 or 0640 protected file | adapter only | revoke and reissue in Grocy, replace the protected file, then rerun install | encrypted secret backup or documented revocation/reissue |
| Agent Zero bounded credential | Agent Zero bridge | optional owner capability | file-backed scoped credential | Agent Zero bridge only | revoke/replace independently | encrypted private backup when state depends on it |
| SearXNG provider settings | SearXNG | optional | private settings file; search cache is not canonical | SearXNG only | regenerate from provider configuration | configuration only, not cache |
| `HADES_OPEN_WEBUI_COMPOSE_FILE`, `HADES_HINDSIGHT_COMPOSE_FILE`, `HADES_SEARXNG_COMPOSE_FILE`, `HADES_HERMES_SERVICE_FILE` | legacy installer compatibility | temporary | paths to old mode 0600 or 0640 records; they do not earn V1 generated-reconstruction evidence | installer/root | migrate to `scripts/render-deployment-records.sh` | record itself, excluding embedded secrets |
| `HADES_OPEN_WEBUI_IMAGE`, `HADES_OPEN_WEBUI_DATA`, `HADES_HINDSIGHT_DATA`, `HADES_SEARXNG_DATA` | generated deployment renderer | yes | immutable built image reference and explicit state paths | renderer/Compose | image is software custody; state paths are restored separately | no image archive or database is embedded in a generated record |
| `HADES_HINDSIGHT_LLM_API_KEY`, `HADES_SEARXNG_SECRET_FILE` | generated application configuration | yes | Hindsight key value and mode-restricted SearXNG secret file | consuming application only | rotate through the component's configuration procedure | never printed or committed; generated SearXNG settings remain protected |
| Hermes release archive | artifact installer | yes | upstream archive selected by `HADES_HERMES_SOURCE_URL` and matching `HADES_HERMES_SOURCE_SHA256` in `config/versions.env` (currently v0.21.2 / `v2026.9.11`) | installer only | obtain a fresh verified archive; never copy a venv | software custody only; it must contain no secrets or owner state |
| Actual endpoint/budget/credentials | finance adapter | owner-gated | explicit authorized environment and scoped references | finance adapter only | owner-controlled | only under authorized finance policy |
| homelab endpoint/credentials | Proxmox/NetBox/Kuma adapters | authorized / credential provisioning | read-only URLs and credentials | homelab adapters only | owner-controlled | only under authorized policy |
| Home Assistant endpoint/token/entity allowlist | HA adapter | owner-gated | URL, scoped token, explicit entity IDs | HA adapter only | owner-controlled | only under authorized policy |
| `HADES_INPUTS_VERSION` | installer | yes | integer contract version; v1 legacy records and v2 generated records are accepted during migration | installer | update only with a documented schema change | record version with deployment evidence |
| `HADES_SYNTHETIC_FIXTURE` | installer/doctor/validator | test-only | `true` only in disposable bundles generated by `scripts/create-generated-private-inputs.sh`; default install/doctor/validation reject it. Full-stack use additionally requires `--synthetic-deployment-test` and the root-owned machine-ID marker created by `scripts/authorize-synthetic-deployment-test.sh` | test harness on the explicitly authorized disposable guest | never remove or change to activate synthetic credentials | never restore into a production deployment |
| `HADES_STATE_ROOT`, `HADES_CONFIG_ROOT`, `HADES_BACKUP_ROOT` | installer/host layout | yes | absolute filesystem paths on the target host | root/operator | migrate only with state-copy and rollback plan | record paths, never state contents in Git |
| `HADES_DEPLOYMENT_DIR` | installer | yes | private record directory containing the four runtime definitions | root/operator | update with a controlled deployment change | preserve the private record bundle |
| `HADES_HERMES_PROFILE` | Hermes service | yes | private profile/state directory; installer provisions the non-login `hades-runtime` service identity and assigns the profile to it | Hermes service account | preserve across reruns; migrate with profile backup | private profile backup and checksum |
| `HADES_HERMES_EXECUTABLE` | Hermes runtime | yes | absolute executable path for the installed manifest-pinned Hermes artifact; checked before installer mutation | installer validates, then Hermes service account runs it | preserve the pinned artifact; upgrade through a separately validated source pin | reconstruct from `scripts/install-hermes-artifact.sh` |
| `HADES_HINDSIGHT_DATABASE_SECRET_FILE` | legacy v1 installer compatibility | v1 only | mode-restricted path retained for legacy private records; not consumed by the current v2 Hindsight template | legacy installer/doctor | retire with the v1-to-v2 record migration | encrypted backup only while legacy records remain |
| `HADES_GROCY_API_KEY_FILE` | Grocy and adapters | required | path to a mode-restricted file containing a key issued by this Grocy instance; arbitrary random strings are invalid. Bootstrap Grocy, change its upstream default password, create the key in **Manage API keys**, then store it here before full HADES installation | consuming service only | revoke and reissue in Grocy, replace the protected file, then rerun install | encrypted secret backup or documented revocation/reissue |
| `HADES_AGENT_ZERO_CREDENTIAL_FILE` | Agent Zero adapter | optional | path to an externally managed mode-restricted API token; not needed when native Operator auth is configured | Hermes profile/runtime only | rotate with Agent Zero credentials and restart Hermes | owner-managed protected secret |
| `HADES_AGENT_ZERO_OPERATOR_PASSWORD_FILE` | Agent Zero native Operator UI and bounded Hermes client | optional | one-line 16-256 character password in a regular non-symlink file, mode 0600 or 0640; unset leaves native UI login disabled by this path | Agent Zero receives it through a mode-0600 env file; after startup the installer reads the token from the running pinned service into a separate mode-0600 Hermes environment file | rotate through the protected input and rerun install; doctor confirms the client token matches the running service | preserve as an owner-held secret or rotate; never print or commit |
| `HADES_AGENT_ZERO_OPERATOR_PROXY_ENABLED`, `HADES_AGENT_ZERO_OPERATOR_PORT` | optional private Agent Zero Operator gateway | disabled by default | set `true` only with native Operator password and all live Phase 3 LLDAP authority inputs; port defaults to 7004 | installer and generated loopback gateway configuration | rerun installer with `false` to stop the gateway and restore the configured direct WebUI bind | no gateway state; retain or rotate LLDAP inputs under their own custody |
| `HADES_EPSILON_PHASE3_DIRECTORY_AUTHORITY_FILE`, `HADES_EPSILON_PHASE3_LLDAP_URL`, `HADES_EPSILON_PHASE3_LLDAP_READER_PASSWORD_FILE` | optional Operator proxy live authorization | optional; gated | stable Open WebUI subject to LLDAP user map and fixed group grants; HTTPS or local loopback HTTP; mode-0600 reader password for `lldap_strict_readonly` | copied to mode-0600 files owned by the Hermes runtime identity only when the Operator proxy is enabled | update mapping or rotate reader credential with the LLDAP procedure, then rerun install | preserve mapping and reader secret using the owner-managed protected backup policy |
| `HADES_SEARXNG_PRIVATE_SETTINGS_FILE` | SearXNG | optional | path to private provider settings | SearXNG only | regenerate from approved provider configuration | configuration backup only |
| `HADES_ACTUAL_ENDPOINT`, `HADES_HOMELAB_ENDPOINT`, `HADES_HOME_ASSISTANT_ENDPOINT` | future adapters | owner-gated | approved endpoint references; no implicit discovery | selected adapter only | owner-controlled | only under authorized policy |

The installer never prints secret contents, copies them into the repository,
or regenerates stable identity material on rerun. A missing or placeholder
required value or required referenced secret file fails before target mutation.
Referenced secret files must be absolute, regular non-symlink files with mode
0600 or 0640. Live finance, homelab, Home
Assistant, household onboarding, Hermes promotion, and off-host recovery
custody remain intentionally outside autonomous reconstruction. Operator input,
private deployment records, and identity-secret paths must be regular files or
directories rather than symlinks, so their provenance and permissions can be
validated without following an untracked path.
